# Keep the pattern catalog current at large review boundaries

At an integration review that covers an epic or several features, the outcome
owner updates the repository's pattern catalog and pathology examples without
a separate extraction outcome, and lists the changes in the completion reply.

Scope:

- Maintenance: candidates are reported during delivery; the catalog pass runs
  at the large review boundary; the bar is three occurrences with the same
  cause; consolidate before adding; only the outcome owner writes.
- A single-feature delivery adds no new entry and may fix an entry its change
  made false.
- Fix the garbled recurrence sentence.
- Work, deliver, review boundaries, and the spec state the same timing.

Acceptance: maintenance, work, deliver, and the spec agree on when catalog
writes happen and who writes them.
